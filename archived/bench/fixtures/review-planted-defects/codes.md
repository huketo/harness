# 지적 코드와 보고 형식

## 코드 목록

아래 여섯 개만 씁니다. 다른 문자열은 유효한 코드가 아닙니다.

| 코드 | 뜻 |
| --- | --- |
| `RACE` | 공유 상태를 `await` 경계를 사이에 두고 검사한 뒤 갱신해, 동시에 도는 다른 실행과 겹칠 수 있음 |
| `UNHANDLED_REJECTION` | 프라미스를 `await` 하지도, `void` + `.catch(...)`로 처리하지도 않아 거부가 처리되지 않음 |
| `OFF_BY_ONE` | 인덱스·경계·길이 계산이 하나 어긋남 |
| `WRONG_ERROR_TYPE` | 규약이 정한 `AppError` 하위 타입 대신 다른 타입을 던짐 |
| `MISSING_CLEANUP` | 획득한 자원(파일 핸들, 타이머, 구독)이 실패 경로에서 해제되지 않음 |
| `CONVENTION` | 위 다섯에 해당하지 않는 `conventions.md` 위반 |

## 보고 형식

`answers/findings.txt`에 한 줄에 하나씩 적습니다.

```
FINDING=<파일>:<줄>:<코드>
```

- `<파일>`은 **변경 후** 파일 경로이며 이 작업 디렉터리 기준입니다. 예: `repo/src/example.ts`. diff의 `b/` 접두는 빼고 적습니다.
- `<줄>`은 **변경 후** 파일에서의 줄 번호입니다. diff 헌크 머리(`@@ -a,b +c,d @@`)의 `+` 쪽 번호가 기준입니다.
- `<코드>`는 위 표의 코드입니다. 대소문자까지 표의 문자열과 정확히 같아야 하며, 그 밖의 문자열은 유효한 지적이 아닙니다.
- 한 줄 예시: `FINDING=repo/src/example.ts:42:RACE`
- `FINDING=`으로 시작하지 않는 줄은 채점에서 무시하므로 주석이나 설명을 함께 적어도 됩니다.
- `FINDING=`으로 시작하는 줄은 모두 하나의 지적으로 셉니다. 그중 위 형식에 맞지 않는 줄(줄 번호가 양의 정수가 아니거나, 코드가 표에 없거나, 구분자가 어긋난 줄)은 **틀린 지적**으로 세어 정밀도를 깎습니다.
