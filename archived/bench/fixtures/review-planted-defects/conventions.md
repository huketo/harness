# 저장소 규약

`repo/`의 TypeScript 코드는 다음 규약을 따릅니다. 리뷰는 이 문서를 기준으로 합니다.

## 1. 오류 타입

- 던지는 값은 언제나 `repo/src/errors.ts`의 `AppError` 하위 타입입니다: `ValidationError`(입력이 계약을 어김), `NotFoundError`(대상이 없음), `TimeoutError`(기한 초과).
- 내장 `Error`, `TypeError`, `RangeError`를 직접 던지거나 문자열·객체를 던지지 않습니다. 상태 코드 대응이 `AppError.code`로만 이뤄지므로 내장 오류는 전부 500으로 새어 나갑니다.
- 하위 계층의 오류를 감쌀 때도 `AppError` 하위 타입으로 다시 던집니다.

## 2. 정리(cleanup)

- 파일 핸들, 타이머, 이벤트 구독처럼 해제가 필요한 자원은 획득한 함수가 성공 경로와 실패 경로 **모두**에서 해제합니다. `try { ... } finally { ... }` 또는 그와 동등한 구조를 씁니다.
- 획득 다음 줄부터 해제 사이에 던질 수 있는 호출이 있으면 `try/finally` 없이 두지 않습니다.
- `setInterval`로 만든 타이머는 종료 경로에서 `clearInterval`로 지웁니다.

## 3. 비동기

- 떠 있는 프라미스를 만들지 않습니다. 모든 프라미스는 `await` 하거나, 의도적으로 기다리지 않을 때만 `void` 연산자와 `.catch(...)`를 함께 붙입니다. `.catch(...)` 없는 `void`도 금지입니다.
- 공유 상태(큐, 카운터, 맵)를 읽어 조건을 판단한 뒤 `await` 경계를 넘어서 그 상태를 바꾸지 않습니다. 검사와 갱신 사이에 `await`가 있으면 그 사이에 다른 실행이 끼어들 수 있습니다. 검사와 갱신은 같은 동기 구간 안에 둡니다.
- 동시에 도는 작업의 수는 `TaskQueue`의 `limit`이 유일한 관리 지점입니다.

## 4. 지속시간과 네이밍

- 지속시간(밀리초) 값은 `repo/src/util/time.ts`의 `seconds()` 또는 `minutes()`로 **선언**합니다. 밀리초 정수 리터럴을 지속시간 값으로 선언하거나 인수로 넘기지 않습니다.
- 모듈 상수는 `SCREAMING_SNAKE_CASE`, 함수와 변수는 `camelCase`, 타입과 클래스는 `PascalCase`입니다.
- 불리언을 돌려주는 이름과 불리언 필드에는 `is`/`has` 접두를 붙입니다.
- `export default`를 쓰지 않습니다. 공개 API는 이름 붙은 `export`로만 내보냅니다.
- 비공개 헬퍼 이름에 `_` 접두를 붙이지 않습니다.

## 5. 경계

- 외부 입력(쿼리 문자열, 파일 경로)은 쓰기 전에 검증하고 실패하면 `ValidationError`를 던집니다.
- 한 번에 읽는 파일 크기와 한 페이지의 최대 항목 수에는 상한을 둡니다.
