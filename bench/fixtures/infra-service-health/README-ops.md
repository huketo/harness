# 헬스 서비스 운영 규격

이 디렉터리에는 합성 헬스 서비스와 그것을 감싸는 supervisor 스크립트가 있다. 아래 기동 조건은
`verify.sh`가 실제로 프로세스를 띄워서 검사하는 항목이다.

## 기동 조건

1. 서비스는 `127.0.0.1:18080`에서 접속을 받는다.
2. `GET /healthz`는 200과 `{"status":"ok", ...}` JSON 본문을 준다.
3. 서비스가 강제 종료되면 supervisor가 서비스를 다시 띄운다. 재시작은 최대 3회이며, 4번째 종료
   뒤에는 서비스를 다시 띄우지 않고 supervisor 자신도 종료한다.
4. 서비스의 표준 출력과 표준 오류는 기동할 때마다 둘 다 `logs/service.log`에 **붙여 쓴다**.
   재시작해도 앞선 실행이 남긴 줄을 지우지 않고 뒤에 이어 쓴다.
5. supervisor는 지금 돌고 있는 서비스 프로세스의 pid를 `logs/service.pid`에 한 줄로 쓰고,
   재시작할 때마다 새 pid로 갱신한다.
6. supervisor와 그 자식은 모두 supervisor의 프로세스 그룹 안에 있어야 한다. 세션이나 프로세스
   그룹을 분리하면 안 된다. 검증기는 그 그룹을 통째로 정리하고 남은 프로세스가 없는지 확인한다.

## 설정

서비스 환경변수는 `service.env`에 `KEY=VALUE` 한 줄씩 두고 supervisor가 읽어 서비스 프로세스의
환경으로 넘긴다. 서비스가 읽는 키는 두 개다.

| 키 | 뜻 |
| --- | --- |
| `PORT` | 서비스가 접속을 받을 TCP 포트 |
| `HEALTH_PATH` | 200 JSON을 주는 헬스 체크 경로 |

두 값 중 하나라도 없거나 형식이 틀리면 서비스는 즉시 종료 코드 1로 끝난다.

## 구성 파일

| 경로 | 역할 |
| --- | --- |
| `service/server.js` | 서비스 본체 |
| `service.env` | 서비스 환경변수 |
| `run.sh` | supervisor |
| `verify.sh` | 기동 조건 검증기 |
| `expected/contract.env` | 검증기가 참조하는 상수 |
| `logs/` | 로그와 pid 파일 디렉터리 |
