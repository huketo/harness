# Slidev: generate, author, present, export

Use this recipe for a new Markdown-first deck. For an existing deck, keep its entry, lockfile, commands, layouts, and asset conventions; change only what the request requires.

## Generate a working project

Run from the repository containing this skill; substitute the installed skill path when necessary:

```bash
node skills/awesome-slides/scripts/new-deck.mjs slidev ./my-talk --style editorial
cd my-talk
npm install
npm run dev -- --port 3030
```

The generator copies the native starter and selected stylesheet to `theme.css`. Choose `editorial`, `signal`, or `technical`; do not copy the engine directory alone and leave its theme import unresolved. The starter pins three direct dependencies (`@slidev/cli` 52.19.1, `@slidev/theme-default` 0.25.0, `vue` 3.5.42). Keep the generated `package-lock.json` with the editable deck; use `npm ci` for subsequent reproduction. `npm install` needs registry access and may run dependency lifecycle scripts.

Start the dev command through the environment's supervised-process mechanism. Observe the ready URL before opening it. This nine-slide, eight-minute Korean showcase contains synthetic data, not reusable business claims. Replace its assertions, figures, caveats, and notes together.

Slidev discovers `layouts/`, `components/`, `setup/`, and `style.css` natively without intermediate schemas. The `As` prefix avoids collisions with theme layouts and utility classes. Use built-in `default`, `center`, `two-cols`, `image-right`, `quote`, or `section` when their composition fits; the default theme's `cover` is not `AsCover`.

When porting an HTML theme, prefix its layout classes and scope typography under the custom `.slidev-layout` root. Do not carry generic `.cover`, `.code`, or `.timeline` names into frontmatter unchanged: active themes or utilities can override alignment, margins, and opacity. Inspect computed styles on visible slides, then verify rendered exports at the deck's actual aspect ratio. Custom layouts use native named slots:

```md
---
layout: AsSplit
---

::header::

# The assertion both columns support

::default::

Evidence or imported code.

::right::

Interpretation, not a duplicate of the evidence.

::footer::

Source, population, and material caveat.

<!--
01:00–02:00 · Explain evidence, then interpretation.
-->
```

Keep presenter notes in the final comment block of each slide, after any scoped style. Check the rendered slide count rather than counting `---`, which also opens YAML frontmatter. For a title in another language, update `htmlAttrs.lang` and the custom layouts' `lang` attributes together.

## Reuse the demonstrated components

The starter demonstrates four domain components adapting BaizeAI talks patterns. Keep `NOTICE.txt` and `licenses/` with redistributed sources.

- `AsBreakdown`: Compares duration totals where the longest scenario sets one common scale. Supply nonnegative finite values in the same unit, unique scenario and segment names, and identical segment order across scenarios. Use two segments: the first accented, the second muted. Zero-length segments retain their text labels. When not to use: negative or diverging data, or many-series legends need an alternate visual rather than misleading input here. Separate observations are not a distribution, average, or percentile.
- `AsStageFlow`: Shows 3–4 short ordered stages at authored canvas size. Stage IDs are unique; highlights mark the intervention without hiding other stages. Arrows encode order, not measured throughput. When not to use: branching logic and loops require an explicit diagram rather than a falsely linear sequence.
- `AsCaseStory`: Keeps a case's reasoning inspectable (observation → interpretation → change → verification). Props are plain text, not HTML. State whether `verified` describes a completed check or a planned experiment; the showcase uses a plan and labels it visibly. Preserve raw observations separately from causal interpretations. Use `rollback` only when the case defines a genuine reversal condition.
- `AsDemoMedia`: Wraps native `<SlidevVideo>` to guarantee accessible static deliverables. Requires `src`, `poster`, `caption`, and `fallback` props; omitting `fallback` fails visibly during development. Videos disappear in PDF and print; the required `fallback` text ensures the takeaway remains readable without media playback.

## Choose the motion that carries the message

Motion serves comprehension, not presentation flair. Reveal items simultaneously when the audience can grasp them together; gate clicks only when the next step answers an anticipated question. Limit `v-mark` to at most one focal point per slide. When not to use arbitrary transitions: varying transition styles slide by slide distracts from content without signaling a structural topic break.

In Slidev, default export without `--with-clicks` renders at `CLICKS_MAX` (`isPrintWithClicks ? 0 : CLICKS_MAX`), capturing each slide's final click state. Ordinary `v-click` elements remain fully visible, but elements hidden via `.hide` disappear from static print, and `v-switch` retains only its final slot. Design rule: never place conclusions or essential takeaways exclusively inside `.hide` elements or early slots of `v-switch`, as they will be omitted from static PDF exports.

- **Transitions**: Frontmatter `transition: slide-left` sets the default; directional `slide-left`/`slide-right` naturally mirrors forward and backward navigation. Override per slide with `transition: slide-up` or `transition: fade`. See [core-animations.md](slidev-official/references/core-animations.md).
- **Clicks and sequencing**: `<v-clicks>` sequences list items. `v-click` reveals elements on step advance. Absolute click steps take scalar integers (`v-click="3"`), while ranges use arrays (`v-click="[2, 5]"` to stay visible during clicks 2 through 5). `v-after` triggers alongside the preceding click. When not to use clicks: do not animate standard bullet lists where simultaneous reading aids comparison.
- **Click dissolve**: `v-click.hide` and `v-after.hide` make the element itself invisible after clicking. Per the static export rule above, hidden elements do not render in default PDF export.
- **Hand-drawn emphasis (`v-mark`)**: Applies Rough Notation shapes: `<span v-mark.underline="1">metric</span>` or `<span v-mark.circle="2">bottleneck</span>`. Also supports `.box`, `.highlight`, and custom colors. When not to use: do not mark multiple phrases on one slide, nor combine competing marker shapes. See [animation-rough-marker.md](slidev-official/references/animation-rough-marker.md).
- **State and physics (`v-motion`, `v-switch`)**: `v-motion` animates layout entries with spring physics (`:initial`, `:enter`). `<v-switch><template #1>Before</template><template #2>After</template></v-switch>` swaps mutually exclusive views; default static export renders only the final slot per the rule above.
- **Presenter click markers (`[click]`)**: Synchronizes presenter note auto-scrolling and line highlighting with slide clicks:
  ```md
  <!--
  Explain baseline metrics
  [click] Explain the intervention
  -->
  ```
  See [animation-click-marker.md](slidev-official/references/animation-click-marker.md).

## Show code changing, not just code

Demonstrate code evolution, highlight exact interventions, and choose verifiable execution tools.

- **Shiki Magic Move**: Morphs code tokens smoothly across evolution steps. Maintain shared variable and function tokens across steps. When not to use: completely swapping unrelated code turns morphing into a jarring flash.
  ````md
  ````md magic-move
  ```ts
  function admit(q: Queue) { return q.depth < 100 }
  ```
  ```ts
  function admit(q: Queue) { return q.depth < 80 ? 'ok' : 'retry' }
  ```
  ```ts
  function admit(q: Queue, c: Client) { return q.depth < 80 ? 'ok' : c.fast ? 'queued' : 'retry' }
  ```
  ````
  ````
  Static export captures the final step per the static export rule above. See [code-magic-move.md](slidev-official/references/code-magic-move.md).
- **Snippet imports and line highlighting**: Import code from tested, maintained source files (`@/...`) rather than duplicating snippets in Markdown: `<<< @/snippets/admission.ts {all|4-7|all}`. Update line ranges when source changes. Slidev defaults the wrapper prop `finally` to `'last'`, applying the final range at `CLICKS_MAX` and dimming other lines in static PDF export. Design rule: ending the highlight sequence with `all` ensures the entire code block remains visible without dimming in static exports. See [code-import-snippet.md](slidev-official/references/code-import-snippet.md) and [code-line-highlighting.md](slidev-official/references/code-line-highlighting.md).
- **Monaco Runner & Twoslash**: Proves live execution (`{monaco-run}`) or TypeScript compiler type inspection (`twoslash`). The starter sets `monaco: false` in headmatter to preserve zero-network offline operation and predictable bundle size. When enabling, verify installed CLI support with `npx slidev --help`. When not to use: do not enable for static presentations, offline delivery without verified pre-bundling, or when print export fidelity is critical. See [editor-monaco-run.md](slidev-official/references/editor-monaco-run.md) and [code-twoslash.md](slidev-official/references/code-twoslash.md).
- **Text diagrams**: Declarative blocks (` ```mermaid `, ` ```latex `) render sequence, architecture, or math notation. The starter prefers local SVG components (such as `AsStageFlow.vue`) to guarantee zero-network rendering, exact brand font control, and instant compilation. Use text diagrams when rapid declarative iteration outweighs strict typography control. See [diagram-mermaid.md](slidev-official/references/diagram-mermaid.md), [diagram-plantuml.md](slidev-official/references/diagram-plantuml.md), and [diagram-latex.md](slidev-official/references/diagram-latex.md).

## Put a demo on the slide

Native media coordination ensures video elements respect slide transitions and presenter controls. Native `<SlidevVideo>` pauses playback on slide exit, resets via `autoreset`, supports `poster`, and gates autoplay on click advance (`v-click autoplay controls`). A plain `<video>` tag ignores slide lifecycle and continues playing in background tabs. See [core-components.md](slidev-official/references/core-components.md).

For static deliverables, follow the `AsDemoMedia` contract above: every embedded video must provide a poster frame and a visible fallback explanation, as video does not play in print.

- **Screen recording guidelines**: Limit demonstration clips to ~10 seconds, muted, showing a single complete user action rather than an endless loop. Record at crisp resolution so UI text remains legible; include a single-line caption describing what is observed. Store local files under `public/` (e.g. `/demo-admission.mp4`). Prefer MP4 for sharper text and smaller file size; use GIF only when player-less auto-looping is mandatory.
- **Prohibited practices**: Never fabricate non-existent product interfaces, embed media from unverified sources, or present standalone video without caption and static fallback.
- **When not to use**: Do not embed screen recordings when a static screenshot with callout annotations explains the interface faster and more clearly.

## Code, reveal, and brand

`setup/shiki.ts` configures GitHub light/dark palettes through `defineShikiSetup` from `@slidev/types`. Keep syntax colors paired with code background. The scoped code rule preserves readable dimmed context. If code is too wide, restructure the snippet or use full-width evidence (`AsEvidence`); shrinking font size globally is not a layout fix. Inspect initial, intermediate, and final states using real navigation; do not force hidden classes visible to inspect them.

Edit `theme.css` for brand roles: `--as-bg`, `--as-fg`, `--as-muted`, `--as-accent`, `--as-line`, `--as-font`, `--as-mono`. `style.css` imports it and scopes slide typography under `.slidev-layout`. Headings use `--as-font-display` and `--as-heading-weight`. Match `colorSchema` (`light` or `dark`) in `slides.md` so Shiki selects the appropriate palette.

The starter disables remote font injection with `fonts.provider: none`. Use a Korean-capable local font stack; embed licensed fonts under `public/` and add `@font-face` only when delivery needs a stable face. Title breaks belong at phrase boundaries; body copy uses Korean `keep-all` wrapping. Asset URLs under `public/` are rooted at `/`; check built URLs under any requested non-root base path. Use local text/SVG for diagrams; inspect computed SVG font sizes against UnoCSS utility conflicts. Pointers: See [style-icons.md](slidev-official/references/style-icons.md) and [core-headmatter.md](slidev-official/references/core-headmatter.md).

## Present and produce the deliverables

1. Open the ready dev URL and step through all 9 slides and clicks. Open presenter mode (`presenter: dev`), verify notes timing (summing to 8 minutes), `[click]` highlights, and video autoplay trigger on click. Interactive charts need a visible static conclusion. Review all notes and synthetic data labels before sharing source. Pointer: See [presenter-timer.md](slidev-official/references/presenter-timer.md).
2. Build the web bundle:

   ```bash
   npm run build
   # For a requested subpath:
   npm run build -- --base /my-talk/
   ```

   Serve `dist/` with a local static server; check navigation, transitions, and local media playback. A dev-server success does not prove the build. This is a web application, not single-file HTML, and scaling down does not make it a 390px mobile handout. If a mobile reading deliverable is requested, provide a separate reading layout or document.
3. Export deliverables after checking installed CLI options:

   ```bash
   npx slidev export --help
   npm install --save-dev --save-exact playwright-chromium
   npm run export -- --output queue-decision.pdf
   ```

   For existing browser installations, install with `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1` and pass `--executable-path /path/to/chromium`. Diagnose missing fonts, assets, or readiness before increasing wait timeouts; a successful export exit code is not a visual pass. Pointer: See [core-exporting.md](slidev-official/references/core-exporting.md).
4. Inspect the actual PDF: 9 pages, complete conclusions, code blocks, Korean glyphs, chart totals, table caveats, video poster and fallback text visible, and no clipping. Check that text is actually selectable rather than assuming text preservation. For per-click exports, invoke `npx slidev export slides.md --with-clicks --output click-steps.pdf`.
5. Non-PDF formats: PPTX export (`npx slidev export slides.md --format pptx --with-clicks false`) produces slide images with presenter notes, **not editable text, shapes, or charts**. Route native PowerPoint editing requirements to native authoring tools. PNG export is for thumbnails or explicit raster delivery, not a substitute for editable source.

Apply [Verification](verification.md). Deliver editable source, lockfile, notices, and exports. Exclude `node_modules`, browser caches, credentials, and workstation absolute paths from deliverables. Publication and persistent hosting require separate authority.
