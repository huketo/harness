# awesome-slides 비교 평가 사례

이 문서는 `suite.json`(스위트 `awesome-slides-compare`, version 4)의 사례 설계를 설명합니다. 평가받는 에이전트에게는 보이지 않습니다. 실행기는 fixture 디렉터리만 작업공간으로 복사합니다. `../evals.json`은 이 스위트에서 생성한 사본이므로 사례를 바꿀 때는 `suite.json`을 고친 뒤 다시 생성합니다.

## 비교 구조

- `none`은 스킬 없이 실행합니다.
- `slides`는 현재 커밋의 `skills/awesome-slides`(Slidev 단일 파이프라인)를 씁니다.
- `slides-prev`는 개편 전 커밋 `096c8fd`의 스킬(34종 HTML 테마 카탈로그와 다중 엔진)을 씁니다.

## 사례별 설계

| 사례 | 확인하려는 것 | 스타일 |
| --- | --- | --- |
| `northstar-design` | 승인된 브리프와 아웃라인을 이어받아, 디자인 용어 없이 고를 수 있는 시안 비교(스무고개 1회차)를 실제 내용으로 보여 주고 멈추는가 | 단계에서 멈춤 |
| `latency-design-md` | 제공된 DESIGN.md를 따라 끝까지 제작하고, 단일 HTML과 PDF를 오프라인·한국어 폰트·잘림 없음으로 검증하는가 | 끝까지 진행 |
| `taskforge-pdf` | 코드 전환과 클릭이 많은 덱을 PDF로 옮길 때 최종 상태와 단계별 쪽을 구분하는가, 없는 영상을 가짜로 만들지 않는가 | 끝까지 진행 |
| `resume-outline` | `status:` 줄로 이어 갈 단계를 찾고, 초안 아웃라인의 승인을 받기 전에 넘어가지 않는가 | 단계에서 멈춤 |
| `workshop-typo` | 다른 엔진 덱의 작은 수정에 파이프라인을 끌어들이지 않는가 (일상 과제) | 최소 수정 |
| `pptx-routing` | 편집 가능한 PowerPoint 요청을 이미지 PPTX로 대신하지 않고 네이티브 PPTX 경로로 다루는가 | 범위 판단 |
| `html-restructure` | 다른 엔진 덱의 구성·디자인 변경을 원본을 지키며 새 덱으로 옮기고, 추정과 조건을 그대로 보존하는가 | 끝까지 진행 |
| `reading-pdf-only` | 혼자 읽는 덱에서 PDF만 전달하고, 설명을 화면에 담는가 | 끝까지 진행 |
| `reference-gate` | 레퍼런스가 있을 때 시안 하나를 보여 주고 이대로 진행할지만 묻고 멈추는가 | 단계에서 멈춤 |

## 판정 메모

- 평가 세션은 질문 도구에 답할 사람이 없습니다. 단계에서 멈추는 사례는 마지막 응답에 질문이 있고 그다음 단계의 산출물이 없으면 통과입니다.
- `northstar-design`의 `final-mentions` 검사는 그림을 보고 고르는 질문의 흔적만 봅니다. 판정 패킷에는 PNG가 들어가지 않으므로, 시안이 실제 내용을 담았는지와 두 시안의 차이가 큰지는 판정자가 시안 소스(theme.css, style.css, slides.md)로 판단합니다. 시각 품질 자체는 이 스위트로 판정되지 않습니다.
- PDF는 바이너리라 채점기의 텍스트 검사로 확인할 수 없어 검사에서 뺐습니다. PDF 품질은 판정자가 에이전트의 보고와 산출물 목록으로만 판단하므로, 이 한계를 결과 해석에 반영합니다.
- 빌드 사례는 `npm ci`, 폰트 내려받기, Playwright의 Chromium 캐시가 필요합니다. 네트워크가 없는 실행에서는 이 사례들의 결과를 해석하지 않습니다.
