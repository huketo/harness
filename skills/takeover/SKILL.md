# Takeover

원래 목표를 끝내는 책임을 지고, 원래 기여자의 공로는 보존한다. 다른 에이전트가 이미 만들었다는 이유만으로 구현을 변호하지 않는다.

1. 원본 MR·PR, 브랜치, 스레드를 읽는다. 리뷰 지적과 사람이 나중에 고쳐 준 내용까지 포함한다. 인계 내용을 실제 코드와 현재 head로 확정하고, 커밋하지 않은 작업이 있으면 그것도 계산한다. 인계는 맥락이지 증거가 아니다.
2. 교체 MR이면 원래 커밋을 새 브랜치로 가져오고 내 수정은 따로 커밋한다. 사람이 원래 MR에서 이어 가거나 쌓아 올리라고 하면 그것을 따른다. 관련 없는 작업을 덮어쓰지 않고, 허락 없이 원래 MR을 바꾸지 않는다.
3. git 작성자와 기존 공동 작성자 trailer를 보존한다. MR 본문에 원래 기여자를 밝히고 원래 MR이 있으면 링크한다. squash 머지가 될 예정이면 머지 커밋에도 사람 작성자·공동 작성자 표기를 남긴다. 이메일은 추측하지 않고 확인된 신원만 쓴다. 모델 표기는 기여자 표기를 대신하지 않는다.
4. `modernize`로 대상 브랜치와 현재 아키텍처에 맞춘다. 같은 목표를 끝내는 데 필요한 것만 다시 만들고, 관련 없는 기능은 손대지 않는다. 의도한 동작과 노출 표면을 빠뜨리지 않으면서 구현을 단순하게 만든다. 작업하는 동안 원본 MR이 나아졌을 수 있으니 다시 확인한다.
5. 원래 실패와 실제 사용 흐름을 저장소 지침과 권한 안에서 독립적으로 확인한다. 모의 객체로 통과한 테스트는 사용자 경험을 증명하지 않는다. 확인하지 못한 것을 적는다.
6. 마무리에 MR이 들어가면 `file-mr`로 올리거나 갱신하고, 만드는 데서 멈추지 않고 `babysit-mr`로 이어 간다. 답글은 `leaving-mr-comments`를 따른다. 원래 MR을 머지하거나 닫는 것은 허락받은 경우에만 한다.
