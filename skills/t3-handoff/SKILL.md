# T3 인계

이 스레드의 작업을 새 최상위 T3 스레드로 넘긴다. 새 스레드는 이 대화를 보지 못하므로, 인계 문서 하나만 읽고도 바로 이어서 일할 수 있어야 한다. 이 스킬을 호출한 것 자체가 새 스레드를 만들어 달라는 사용자의 명시적 요청이다.

시작 전에 `orchestrator_capabilities`를 호출한다. 도구가 없으면 T3 스레드 밖이므로 `handoff` 스킬로 문서만 만들고 멈춘다. 인자가 있으면 새 스레드가 집중할 일로 보고 문서를 그에 맞춘다.

## 1. 넘기기 전에 상태를 고정한다

1. 이 스레드가 띄운 하위 작업(`delegate_task`), 예약 작업, 실행 중인 백그라운드 명령, Herdr pane을 확인한다. 끝나기를 기다릴지, 취소할지, 새 스레드가 이어받을지를 정하고 문서에 적는다. 새 스레드는 이 스레드의 `taskId`로 하위 작업을 조회할 수 없으므로, 이어받을 결과가 있으면 끝날 때까지 기다리거나 결과를 받을 위치를 적는다.
2. `t3_worktree_status`로 이 스레드가 묶인 checkout과 브랜치를 확인한다. 각 저장소의 `git status --short --branch`와 아직 push하지 않은 커밋을 확인한다.
3. 커밋하지 않은 변경은 새 worktree로 복사되지 않는다. 사용자가 커밋을 요청하지 않았다면 커밋하지 않고, 새 스레드를 같은 checkout에 묶는다.

## 2. 인계 문서를 쓴다

새 스레드가 처음 읽을 문서다. 이 대화에서만 알 수 있는 사실을 담고, 저장소나 다른 산출물에 이미 있는 내용은 경로나 URL로 가리킨다.

- **목표와 완료 기준**: 사용자가 원하는 결과, 완료를 판정할 명령이나 관측.
- **현재 상태**: 끝난 일, 진행 중인 일, 남은 일. 저장소마다 경로, 브랜치, 마지막 커밋, 커밋하지 않은 변경, push 여부를 적는다.
- **결정과 근거**: 사용자가 내린 결정, 이미 기각한 대안과 그 이유. 사용자가 승인한 범위와 아직 승인받지 않은 행동(push, merge, 삭제, 예약 작업 변경, 외부 쓰기)을 구분한다. 승인은 이 스레드의 맥락에서만 유효하므로, 아직 실행하지 않은 외부 쓰기는 새 스레드가 다시 확인하도록 적는다.
- **주의할 점**: 실패한 시도, 재현 방법, 건드리면 안 되는 파일이나 실행 중인 작업, 시간 제약.
- **다음 행동**: 새 스레드가 처음 할 일을 순서대로 적는다.
- **권장 스킬**: 새 스레드가 불러야 할 스킬과 그 이유.

비밀값, 토큰, 개인 정보는 넣지 않는다. 필요하면 어디서 읽는지만 적는다. 문서 사본은 `${TMPDIR:-/tmp}/t3-handoff/<YYYYMMDD-HHMM>-<짧은-이름>.md`에 저장한다. 작업 중인 저장소에는 저장하지 않는다.

## 3. 새 스레드를 띄운다

`t3_thread_launch`를 한 번 호출한다.

- `title`: 이어서 할 일을 드러내는 짧은 제목.
- `message`: 인계 문서 전문. 첫 줄에 "이전 스레드에서 넘겨받은 작업입니다. 아래 인계 문서를 기준으로 이어서 진행하고, 문서와 실제 상태가 다르면 실제 상태를 먼저 확인합니다."를 둔다.
- `workspaceStrategy`: 이 스레드가 worktree에 묶여 있으면 `{type:"existing_worktree", worktreePath, branch}`, 프로젝트 checkout이면 `{type:"root"}`로 같은 작업 공간을 지정한다. 생략하면 이 스레드의 worktree가 아니라 프로젝트 루트로 간다. 사용자가 새 브랜치나 다른 위치를 요청했고 넘길 변경이 모두 커밋되어 있을 때만 `{type:"worktree", baseRef, branch, startFromOrigin:false}`를 쓴다.
- `projectId`, `modelSelection`, `runtimeMode`, `interactionMode`는 생략해 이 스레드의 값을 물려준다. 사용자가 다른 모델을 지정했을 때만 `modelSelection`을 넣는다. 새 스레드는 이 스레드보다 넓은 실행 모드를 가질 수 없다.

호출에는 재시도 키가 없다. 오류가 나거나 응답을 받지 못했으면 다시 호출하기 전에 `t3_thread_list`로 같은 제목의 스레드가 이미 생겼는지 확인한다. 반환된 `threadId`로 `t3_thread_read`를 한 번 읽어 작업 공간 준비가 실패하지 않았는지 확인한다. 새 스레드의 작업이 끝나기를 기다리지는 않는다.

## 4. 이 스레드를 멈춘다

같은 checkout을 두 스레드가 동시에 고치지 않도록, 인계한 뒤에는 이 스레드에서 파일을 고치거나 명령을 실행하지 않는다. 마지막 응답에는 다음을 적는다.

- 새 스레드 링크: `[제목](t3-thread://v1/<threadId>)` 형식이며 `threadId`는 반환값 그대로 쓴다.
- 문서 사본의 경로.
- 새 스레드에 넘기지 못한 것(취소한 하위 작업, 아직 실행 중인 명령 등).
