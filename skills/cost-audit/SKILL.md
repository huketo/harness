# OMP 비용 감사

세션 통계와 JSONL 근거를 연결하여 비용 낭비를 찾고, 관측값에 맞는 설정 변경을 제안합니다.

## 절차

1. 분석 직전에 `omp stats --summary`를 실행하여 `~/.omp/stats.db`를 동기화합니다. 동기화가 실패하면 기존 수치를 최신값처럼 보고하지 않습니다.
2. 스킬 디렉터리의 분석기를 실행합니다. 기본 감사는 다음 명령을 사용합니다.

   ```bash
   python3 "$HOME/.agents/skills/cost-audit/analyze.py" --days 7 --format markdown
   ```

   프로젝트는 `--folder <부분문자열>`, 단일 세션은 `--session <JSONL 경로 또는 세션 ID 앞글자>`로 좁힙니다. 기계 처리는 `--format json`, 파일 저장은 `--out <경로>`, 변경 전후 기준선만 비교할 때는 `--baseline`을 사용합니다. 임계값을 바꿀 명확한 근거가 있을 때만 `--ctx-threshold`를 지정합니다.
3. 기준선에서 요청 수, 모델별 지출, 네 가지 비용 구성, 캐시 적중률, main·subagent 분해를 먼저 확인한 뒤 탐지 결과를 금액순으로 해석합니다. 사례의 세션 경로와 토큰 수를 근거로 함께 제시합니다.
4. 조치에는 적용 대상을 모호하게 쓰지 말고 실제 설정 키를 명시합니다. 캐시 보존은 `providers.cacheRetention`, 역할 라우팅은 `task.agentModelOverrides`와 `modelRoles.smol`·`modelRoles.mid`, 압축은 `compaction.thresholdTokens`, 재시도 경로는 `retry.fallbackChains`를 사용합니다. 관측된 순이익이 음수인 설정 변경은 권장하지 않습니다.
5. 설정을 바꾸면 같은 기간과 필터로 기준선을 다시 계산하여 변경 전 결과와 비교합니다. 기간이나 대상 세션이 다르면 개선으로 단정하지 않습니다.

사용자가 보고서 문서를 요청하면 분석기의 Markdown 또는 JSON을 근거 데이터로 만들고 `writing-for-humans` 스킬의 작성·검수 절차를 따릅니다. HTML 보고서는 그 스킬의 FORMATS.md HTML 절이 맡습니다.

## 해석 원칙

- 금액은 구독 계정 사용량에 카탈로그 단가를 적용한 명목 환산치이며 실제 청구액이 아닙니다.
- 도구 결과 비용은 문자 수를 토큰 수로 근사합니다. 실제 토큰화, 압축 경계, 캐시 prefix 경계가 없으므로 정밀한 청구 계산처럼 제시하지 않습니다.
- 기본 임계값은 `docs/FACTS.md`에 기록된 사용자 환경의 최근 실측값에서 유래했습니다. 다른 기간이나 프로젝트에 보편적인 기준으로 일반화하지 않습니다.
- `models.db`의 현재 단가로 계산한 반사실 비용과 실제 관측 비용을 구분합니다. `stats.db`에는 subagent의 smol·mid 역할이 없으므로 두 라우팅 결과를 임의로 하나에 귀속하지 않습니다.

탐지기와 계산식, CLI 전체 설명은 [README.md](README.md)에 있습니다. `--format json` 결과를 질의하기 전에 README의 탐지기·기준선 절에서 필드 이름을 확인하고, 문서에 없으면 `jq keys`로 한 번 확인합니다. 추측한 필드 이름으로 질의하지 않으며, Markdown 보고서에 이미 있는 수치는 JSON에서 다시 구하지 않습니다.
