# Formal verify

테스트는 누군가 떠올린 경우만 확인한다. 이 스킬은 정한 범위의 모든 경우를 확인한다: 모델 안의 모든 실행 순서, 한계까지의 모든 입력, 또는 생성한 많은 입력. 버그의 대가가 가장 크고 테스트가 가장 닿지 않는 곳을 하나 골라 속성 하나를 검증하고, 다음 에이전트가 변경마다 그 속성을 다시 확인할 수 있게 남긴다.

모든 저장소에 쓰는 기본 절차가 아니다. 상태 기계, 동시성, 재시도, 파서, 직렬화처럼 경우의 수가 예시로 덮이지 않는 곳에만 쓴다.

## 1. 대상을 코드에서 고른다

사람이 영역이나 버그를 지정했으면 거기서 시작한다. 좋은 대상은 코드가 하는 약속 가운데, 깨지면 사용자가 피해를 보고 테스트가 깨지는 경우에 거의 닿지 않는 것이다. 검증하기 쉬운 대상이 아니라 그런 대상 가운데 가장 중요한 것을 고른다.

완료 기준: 속성과 그 속성이 깨졌을 때의 피해를 각각 평이한 한 문장으로 적었다.

## 2. 질문이 도구를 고른다

| 질문 | 맞는 도구 |
| --- | --- |
| 사건이 나쁜 순서로 일어날 수 있는가 | 설계를 작게 옮긴 모델에 대한 모델 검사(TLA+와 TLC가 기본값이다) |
| 코드가 모든 입력에서 속성을 지키는가 | 그 언어의 코드에 직접 도는 검증기. 없으면 실제 코드에 생성한 입력을 넣는 속성 기반 테스트(TypeScript는 fast-check, Python은 Hypothesis) |
| 한계가 아니라 모든 크기에서 성립해야 하는가 | 증명 보조기 |

저장소의 개발자가 설치하고 실행할 수 있는 도구를 우선한다. 손으로 다시 쓴 함수의 모형이 아니라 실제 코드를 검사한다. 고른 이유를 사람에게 말한다.

## 3. 좋은 검증의 조건

- **코드에 충실하다.** 모델이나 속성의 각 부분이 리뷰어가 열어 볼 수 있는 코드를 가리킨다. 검증이 한 단계로 다루는 것은 코드에서도 나눌 수 없는 한 단계다. 이름은 이 저장소의 것을 쓴다.
- **실패할 수 있다.** 지키는 코드를 일부러 깨뜨린 변형(검사 하나 제거, 순서 바꿈)에서 속성이 실패하는 것을 본다. 실패하는 것을 본 적이 없는 검사는 아무것도 증명하지 않는다.
- **발견은 발견으로 남는다.** 현재 코드가 속성을 깨면 반례를 코드의 말로 보고한다. 통과할 때까지 속성이나 모델을 약하게 만들지 않고, 사람이 요청하지 않으면 제품 코드를 고치지 않는다.
- **범위에 정직하다.** 무엇을 어떤 한계와 가정 아래 검증했고 무엇이 빠졌는지 적는다. 통과는 모델이나 한계까지만 덮는다.
- **도구 없이 읽힌다.** 반례는 코드의 말로 쓴 짧은 단계의 나열로 전한다.
- **다시 돌리기 쉽다.** 명령 하나, 고정된 도구 버전과 난수 seed, 관련 변경마다 돌릴 만큼 짧은 실행 시간.

## 4. 다시 돌릴 자리에 둔다

속성 기반 테스트는 저장소의 테스트 실행기 안에 두어 check 명령과 CI가 함께 돌린다. 저장소의 실행기로 돌릴 수 없는 검증(모델 검사)은 저장소 전용 스킬 `.agents/skills/formal-<영역>/`으로 남기고, Claude Code가 읽도록 `.claude/skills/formal-<영역>`을 `../../.agents/skills/formal-<영역>`으로 가는 상대 심링크로 둔다. `verify-` 접두사는 쓰지 않는다. 그 이름은 앱을 실행해 증명하는 검증 스킬의 것이고 `full-send`가 그 이름으로 준비 상태를 판단한다. 그 스킬만 읽고도 다음 에이전트가 아래 일을 할 수 있어야 한다.

- 변경이 검증된 코드를 건드리는지 판단한다. 검사마다 덮는 파일과 함수, 그리고 검증이 코드를 기술한다고 마지막으로 확인한 커밋을 적어 둔다.
- 검사를 실행한다.
- 실제 버그와 모델의 오류를 구분한다.
- 의도한 변경이면 검증을 고친다. 확인 커밋은 검증이 새 코드를 기술한다고 확인한 뒤에만 옮긴다.

## 5. 넘기기 전에 증명한다

속성을 깨는 임시 변경을 만들고, 다음 에이전트가 하듯 남긴 명령을 실행한다. 검사가 그 변경을 잡아야 한다.

- 실제 코드에 도는 검사(속성 기반 테스트, 코드 검증기)는 제품 코드를 깨뜨린다.
- 모델 검사는 코드를 읽지 않으므로 모델을 깨뜨린다. 속성을 지키는 전이 하나의 조건을 모델에서 지우고 반례가 나오는지 본다. 그리고 그 전이가 가리키는 코드를 열어 모델의 조건이 코드에 실제로 있는지 따로 확인한다.

임시 변경을 되돌리고 검사가 처음 상태(통과, 또는 보고할 발견에서만 실패)로 돌아오는지 확인한다. 검사가 변경을 놓치면 임시 변경이 아니라 검증을 고친다.

완료 기준: 깨뜨린 코드나 모델에서 실패한 출력과 되돌린 뒤 통과한 출력이 있다.

## 보고

검증한 속성, 고른 도구와 이유, 한계와 가정, 발견한 것(코드의 말로), 실행 명령, 덮지 않는 것을 적는다.
