# HTML 보고서

파일 하나로 전달되는 보고서. 독자는 저장소, 사내 문서, 이전 대화, 개발 환경에 접근하지 않는다. 그 파일만 열어서 내용을 이해할 수 있어야 하고, 근거를 더 보고 싶을 때만 공개 URL을 따라간다.

## 작업 순서

1. **질문과 독자 확정** — 보고서가 답하는 질문 한 문장, 독자가 이 보고서로 내리는 판단 한 문장을 먼저 적는다. 둘 중 하나라도 적히지 않으면 사용자에게 확인한다.
2. **근거 확정** — 보고할 주장마다 근거를 확보한다. 근거는 본문에 인용해 넣을 수 있는 형태(수치, 코드 인용, 로그, 명령 출력, 실행 결과)이거나 공개 URL이다. 근거를 확보하지 못한 주장은 결론으로 쓰지 않고 미확인 항목으로 분류한다.
3. **작성** — [template.html](template.html)을 복사해 시작한다. [문서 구조](#문서-구조), [자기완결](#자기완결), [single-file](#single-file), [용어와 문장](#용어와-문장)을 적용한다. 다이어그램을 넣으면 [SVG-DIAGRAMS.md](SVG-DIAGRAMS.md)를 읽고 그린다.
4. **검수** — [검수](#검수) 항목 전부를 실제 렌더 결과로 확인한다. 하나라도 실패하면 고치고 다시 렌더한다.
5. **전달** — 저장 절대 경로, 보고서가 답한 질문, 결론 한 줄, 미확인으로 남긴 항목을 보고한다.

경로를 지정받지 않았으면 작업 디렉터리에 `<주제-kebab>-report.html`로 쓴다.

## 문서 구조

- **머리** — 제목, 작성일, 작성자, 대상 시스템과 버전·커밋·기간 등 보고 범위를 특정하는 값.
- **요약** — 질문, 결론, 결론의 근거 한 줄, 독자가 취할 행동. 5줄 이내.
- **본문** — 섹션마다 하나의 발견을 다룬다. 각 섹션은 주장 → 근거(수치·인용·다이어그램) → 영향 순서로 적는다.
- **미확인과 한계** — 확인하지 못한 것, 측정 범위 밖의 것, 결론이 뒤집힐 조건.
- **출처** — 본문에서 링크한 URL 목록. 각 항목에 그 URL이 뒷받침하는 주장을 한 줄로 붙인다.

목차는 섹션이 5개를 넘을 때만 넣는다.

## 자기완결

- 판단에 필요한 사실은 본문에 직접 적는다. 코드는 해당 줄을 인용해 넣고, 수치는 값과 측정 조건을 함께 적고, 로그는 필요한 줄만 잘라 넣는다.
- 저장소 경로, 로컬 파일 경로, 사내 문서 경로, 이전 보고서, 대화 맥락, 이슈 번호 단독 표기는 보고서에 쓰지 않는다. 독자가 열 수 없는 참조다. 파일 경로를 사실의 위치 표시로 적는 것은 허용되며, 그 경로의 내용은 인용으로 본문에 들어간다.
- 외부 링크는 독자가 공개적으로 열 수 있는 1차 출처만 쓴다. 공식 문서, 명세·RFC, 오픈소스 저장소의 파일·커밋·이슈, 검증된 기술 포스트. 링크는 그 링크가 뒷받침하는 문장 옆에 붙인다.
- 링크를 하나도 열지 않아도 보고서 전체가 읽히는 상태를 유지한다. 링크는 근거 보강이고, 독해 경로가 아니다.
- 약어와 전문용어는 첫 등장에 한 줄로 정의한다.

## single-file

- 파일 하나를 복사하거나 메일에 첨부하면 그대로 재현된다. 이 조건이 형식을 결정한다.
- CSS는 `<style>`에, 스크립트는 `<script>` 본문에 넣는다. 그림은 인라인 SVG로 그린다.
- CDN, 외부 스타일시트, 웹폰트 요청, 외부·로컬 이미지 파일, 빌드 산출물 참조는 쓰지 않는다. `<a href>`의 1차 출처 링크만 문서 밖을 가리킨다.
- 폰트는 `template.html`의 시스템 폰트 스택을 쓴다.
- 스크립트는 렌더에 필요할 때만 넣는다. 정적 HTML로 표현되는 내용은 정적으로 둔다.

## 용어와 문장

- 정확히 대응하는 한국어가 없는 전문용어는 원어 표기를 그대로 쓴다: deadlock, throughput, race condition, cold start, backpressure. 임의로 번역해 새 용어를 만들지 않는다.
- 대응하는 한국어가 정착된 용어는 한국어로 쓴다: 인증, 캐시, 배포, 병렬. 한 문서 안에서 같은 개념은 같은 표기로 고정한다.
- 관찰하고 측정한 사실과 수치로 서술한다. 비유, 은유, 의인화, 과장, 감정 표현, 수사적 질문은 쓰지 않는다.
- 단정할 수 있는 것은 단정하고, 추정은 추정이라고 적으며 근거와 남는 불확실성을 함께 적는다.
- 형용사보다 수치를 쓴다. "느리다"가 아니라 "p95 1.8초, 목표 300ms".

## 반응형

독자는 데스크톱 브라우저와 휴대폰 브라우저 중 어느 쪽으로도 열 수 있다. 두 폭에서 모두 읽히는 상태가 완성 조건이다.

- `template.html`의 `<meta name="viewport">`, `clamp()` 기반 여백·제목 크기, 560px 미디어 쿼리, `color-scheme: only light`를 유지한다. `only light`는 휴대폰 브라우저의 자동 다크 변환이 다이어그램 색을 반전시키는 것을 막는다.
- 본문 글자 크기는 16px 이상으로 둔다. 휴대폰 브라우저가 확대 없이 읽을 수 있는 하한이다.
- 표는 `<div class="table-wrap">`으로 감싼다. 좁은 폭에서 표만 가로 스크롤되고 본문은 접힌다. 열이 6개를 넘으면 표를 나누거나 행 단위 목록으로 바꾼다.
- 긴 코드 인용은 줄을 80자 이내로 잘라 넣는다. `<pre>`는 가로 스크롤되지만 스크롤 폭이 길수록 읽히지 않는다.
- 고정 픽셀 폭, `position: fixed`, 좌우 2단 레이아웃은 쓰지 않는다. 단은 하나로 두고 세로로 쌓는다.
- 다이어그램은 좁은 폭에서 가로 스크롤을 허용한다. 그 대신 `<figcaption>`이 그림 없이도 사실을 전달한다.

## 검수

브라우저 도구로 `file://<절대경로>`를 열고 아래 전부를 확인한다. 전부 통과한 렌더 결과를 본 뒤에만 전달한다.

1. **외부 요청 0건** — `performance.getEntriesByType('resource').map(r => r.name)`이 빈 배열이다.
2. **링크** — 목차의 `#anchor`를 뺀 외부 링크를 모으고, 각 URL이 실제로 열리고 본문이 인용한 내용을 담고 있는지 확인한다: `[...document.querySelectorAll('a[href]')].filter(a => !a.getAttribute('href').startsWith('#')).map(a => a.href)`. `file:`, 상대 경로, 사내 호스트, 로그인이 필요한 URL이 있으면 자기완결 위반이므로 본문 인용으로 바꾼다. 문서 안의 `#anchor`는 대상 요소가 존재하는지만 확인한다.
3. **다이어그램** — SVG가 있으면 [SVG-DIAGRAMS.md](SVG-DIAGRAMS.md)의 audit 결과가 빈 배열이고, 각 다이어그램을 selector로 스크린샷해 이미지를 직접 본다. 노드와 화살표가 의도한 관계를 그리고 있는지, 라벨이 가려지거나 잘리지 않았는지 이미지로 판단한다.
4. **반응형** — 1280px에서 표·코드 블록·다이어그램이 잘리지 않는다. 390px과 360px에서 본문·제목·표 머리·`dl.meta`가 가로로 잘리지 않고, 가로 스크롤이 생기는 요소는 `.diagram`, `.table-wrap`, `<pre>`뿐이다: `[...document.querySelectorAll('body *:not(svg *)')].filter(el => el.scrollWidth > el.clientWidth + 1).map(el => el.getAttribute('class') || el.tagName)`. SVG 내부 요소는 제외한다. `<text>`의 `scrollWidth`는 레이아웃 박스와 어긋나 오탐을 내고, 잘림 검사는 3번 audit이 담당한다. 두 폭 모두 전체 스크린샷으로 확인한다.
5. **구조** — 요약, 미확인과 한계, 출처가 모두 채워져 있다. 빈 섹션과 `{{ }}` 자리표시자가 남아 있지 않다.
