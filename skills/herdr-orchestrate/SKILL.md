# Herdr 오케스트레이션

이 세션이 오케스트레이터다. 목표를 슬라이스로 나누고, 슬라이스마다 워크트리 워크스페이스와 워커를 만들고, 독립 리뷰어로 검수하고, 통합 브랜치에 합친다. 상태는 파일에 두고 화면은 믿지 않는다.

시작 전에 `test "${HERDR_ENV:-}" = 1`을 확인한다. 실패하면 Herdr 밖이라고 말하고 멈춘다. herdr 명령의 문법은 `herdr <group>`으로 현재 바이너리에서 확인하고, 검증된 실행 레시피는 [references/launch.md](references/launch.md)를 따른다.

## 역할

| 역할 | 실행기 | 하는 일 |
| --- | --- | --- |
| 오케스트레이터 | 이 세션 | 분해, 브리프, 감시, 검수 판정, 통합, 사람과의 유일한 접점 |
| 워커 | omp | 슬라이스 하나를 자기 워크트리에서 구현하고 브랜치에 커밋, `report.md` 작성 |
| 리뷰어 | 제한 SDK 진입점, 워커와 다른 모델 계열 | 미리 저장된 diff와 파일만 읽고 [references/review.md](references/review.md) 기준으로 stdout 판정 |
| 스카우트 | agy 또는 omp | 웹·문서 조사. 출처 URL 필수 |
| 쿼럼 | 세 계열 혼합 | 갈리는 기술 결정을 `herdr-quorum` 스킬로 결정 |

실행기 선택. `herdr integration status`에서 `current`인 종류만 쓴다. 기본 워커는 omp다. Herdr의 생명주기와 산출물 완료는 구분한다. 실행·대기·인계 판정은 [launch.md](references/launch.md)가 소유하며, 리뷰는 그 문서의 제한 reviewer 경로를 따른다. 웹 조사에 적합한 실행기를 스카우트에 사용한다.

모델 다양성. 독립 리뷰가 필요하면 워커와 다른 모델 계열과 새 컨텍스트를 우선한다. 독립성은 확인 가능한 근거를 대신하지 않는다. `omp models`와 `herdr integration status`로 후보를 확인하고 실제 모델 계열을 기록한다. AGY의 Claude와 OMP의 Claude를 다른 계열로 세지 않는다.

용도별 선택은 `omp-profile list`가 있으면 그 목록을 따른다. 기본 역할을 다시 설정하는 대신 실행할 프로필의 전체 모델·effort를 자식 프로세스에 넘긴다. 프론트엔드·오케스트레이션·어려운 구현과 일반 구현, 저비용 작업, 검색·미디어를 구분하고 실제 선택을 `run.md`에 남긴다. 기존 대화의 모델 계열을 바꿀 때에는 읽을 수 있는 인계문을 먼저 만들며, 다른 제공자의 암호화된 압축 상태를 전달하지 않는다.

통합과 완료 책임은 이 세션에 남긴다. 워커가 소유한 파일을 동시에 고치지 않으며, 공통 계약과 통합 영역은 직접 처리한다. 워커가 막혔으면 원인과 남은 범위를 확인하고 소유권을 인계받아 마무리할 수 있다. 위임은 완료 책임을 넘기는 절차가 아니다.

## 절차

### 1. 범위와 수용 기준

1. 목표를 한 문장으로 적고, 완료를 판정할 관측 가능한 기준을 항목으로 적는다. 기준에는 실행할 명령이 들어간다(테스트, 빌드, 스모크).
2. 변경 경로에 필요한 저장소 관례와 검증 방법을 확인한다. 이미 확인한 사실은 재사용하고, 관련 지침은 해당 절의 경로로 넘긴다.
3. 사람에게 물을 것이 있으면 이 단계에서 한 번에 묻는다. 방법은 "사람 개입" 절.

### 2. 슬라이스 분해와 그래프

슬라이스는 소유 파일이 겹치지 않고 관측 가능한 결과로 끝나는 독립 작업이다. 직접 처리하는 것보다 조사·전달·검수 비용이 적을 때만 위임한다. 사소한 함수 수정이나 경계가 없는 "전체 마이그레이션"을 별도 워커로 만들지 않는다.

1. 각 슬라이스에 소유 파일 집합을 준다. 두 슬라이스가 같은 파일을 고치면 하나로 합치거나 순서를 정한다.
2. 슬라이스 사이의 계약(인터페이스, 스키마, 함수 시그니처)은 오케스트레이터가 지금 정해서 양쪽 브리프에 같은 문장으로 적는다. 워커끼리 협상시키지 않는다.
3. 의존 관계를 그래프로 적는다. 의존이 없는 슬라이스가 한 웨이브다. 다음 웨이브는 의존 슬라이스가 통합 브랜치에 합쳐진 뒤 시작한다.
4. 동시 워커는 3~5개에서 시작한다. 그 이상은 조정 비용이 병렬 이득을 넘는다.

결과는 `run.md`의 슬라이스 표에 적는다(레이아웃은 "상태 파일" 절).

### 3. 이름과 배치

Herdr 사이드바와 `herdr agent list`가 곧 상태판이다. 이름이 역할·슬라이스·단계를 드러내지 않으면 상태판이 아니다.

| 대상 | 규칙 | 예 |
| --- | --- | --- |
| 실행 슬러그 `<run>` | 케밥, 8자 이내 | `authref` |
| 슬라이스 슬러그 `<slice>` | 케밥, 14자 이내 | `token-store` |
| 브랜치 | `orch/<run>/<slice>`, 통합은 `orch/<run>/integrate` | `orch/authref/token-store` |
| 워크스페이스 라벨 | `<run>/<slice>`, 통합은 `<run>/integrate` | `authref/token-store` |
| 탭 라벨 | 단계 이름 `work`, `verify`, `review` | |
| 페인 라벨 | `<역할>:<slice>` | `worker:token-store`, `review:token-store` |
| 에이전트 이름 | `<run>-<역할>-<slice>`, 역할은 `work` `rev` `scout` `voice` `int` | `authref-work-token-store` |
| 오케스트레이터 | 자기 탭과 페인을 `orch:<run>`으로 | |

에이전트 이름은 `[a-z][a-z0-9_-]{0,31}`이고 살아 있는 모든 에이전트 사이에서 고유해야 한다. 다른 워크스페이스의 에이전트도 포함되므로 실행 슬러그를 반드시 넣는다.

배치.

1. 슬라이스마다 `herdr worktree create --workspace "$HERDR_WORKSPACE_ID" --branch orch/<run>/<slice> --base <기준 ref> --label <run>/<slice> --no-focus`. 응답의 `.result.workspace.workspace_id`, `.result.root_pane.pane_id`, `.result.workspace.worktree.checkout_path`를 `run.md`에 적는다. 워크트리 경로는 응답에서 읽고 추측하지 않는다.
2. 그 워크스페이스의 첫 탭을 `work`로 이름 짓고 루트 페인에 워커를 띄운다. 검증 명령용 페인은 같은 탭에서 아래로 분할해 `verify:<slice>`로, 리뷰어는 `review` 탭을 만들어 띄운다.
3. 통합 워크트리 `orch/<run>/integrate`를 하나 만든다. 사용자의 원래 체크아웃은 건드리지 않는다.
4. 페인을 새로 띄울 때는 `--no-focus`다. 사용자의 포커스는 사용자 것이다.

### 4. 브리프와 실행

워커는 오케스트레이터의 대화를 모른다. 브리프 파일이 워커가 아는 전부이므로 [references/brief.md](references/brief.md)의 양식대로 슬라이스 디렉터리에 `brief.md`를 쓰고, 프롬프트는 한 줄로 그 파일을 가리킨다.

```sh
herdr agent start <run>-work-<slice> --kind omp --pane <pane> -- --approval-mode yolo
herdr agent prompt <run>-work-<slice> "Read <state>/slices/<slice>/brief.md and carry it out exactly." --wait --timeout 1800000
```

`--approval-mode yolo`는 워크트리 격리를 안전 경계로 삼아 승인 대화창으로 멈추지 않게 한다. 워크트리 밖을 만지는 작업이 브리프에 있으면 yolo를 쓰지 않고 `blocked` 상태를 감시한다.

워커에게 주는 규칙(브리프에 들어 있다): 소유 파일만 고친다, 자기 슬라이스의 테스트만 돌린다, 사람에게 묻지 않고 `report.md`의 "결정 필요"에 적고 멈춘다, 끝나면 브랜치에 커밋하고 `report.md` 마지막 줄에 `REPORT_DONE`을 쓴다.

웨이브를 띄울 때는 프롬프트를 `--wait` 없이 보내고, 워커마다 `herdr agent wait <name> --timeout`을 순서대로 불러 기다린다(launch.md). `sleep` 루프나 `agent list` 반복으로 폴링하지 않는다. 돌아온 상태가 `blocked`면 `agent read`로 화면을 읽고 원인이 승인창이면 브리프 위반인지 판단한 뒤 답한다.

### 5. 슬라이스 루프

슬라이스 하나는 평가-최적화 루프다. 회차마다 리뷰어는 새 컨텍스트다.

1. `report.md`에 `REPORT_DONE`이 있고 브랜치에 커밋이 있는지 확인한다. 없으면 완료가 아니다.
2. 수용 기준의 명령을 직접 실행한다. 짧은 검증은 native 도구로, 오래 걸리거나 사람이 관찰·조작할 실행은 명시한 Herdr 페인으로 수행한다. 워커의 "통과했다"는 근거가 아니라 주장이다.
3. [references/launch.md](references/launch.md)의 제한 reviewer를 새 컨텍스트로 실행하고 [references/review.md](references/review.md)의 브리프를 준다. 오케스트레이터가 저장한 diff와 커밋 목록, 수용 기준, 관례 문서 경로를 입력으로 제공하고 stdout 판정을 review 파일에 저장한다. 워커의 `report.md`는 첫 판정 뒤에만 대조한다.
4. `review-<n>.md`의 `blocking`을 근거(`file:line`, 재현 명령, 참고 URL)로 판정한다. 확인되지 않은 주장을 그대로 워커에게 보내지 않는다. 확인된 `blocking`이 없으면 통과하며, 반복 검토는 새 결함·변경·근거가 있을 때만 한다. 사실은 먼저 직접 확인하고, 중요한 선택지가 근거로 계속 갈릴 때만 `herdr-quorum`을 사용한다.
5. 같은 문제가 반복되면 재현과 실패 원인을 확인하고 접근을 바꾼다. 새 컨텍스트가 필요할 때만 `handoff.md`에 완료한 일·남은 범위·근거를 남기고 워커를 교체한다. 근거 없이 같은 리뷰를 다시 요청하지 않는다.
6. 리뷰 3회차를 넘기면 루프를 멈추고 `run.md`에 막힌 이유를 적는다. 기술적 갈림이면 쿼럼, 요구사항 갈림이면 사람.

리뷰어가 "이 저장소의 기존 관례 자체가 비표준"이라고 표시한 항목은 워커에게 고치라고 보내지 않는다. 관례 변경은 결정이므로 `decisions.md`에 올리고 쿼럼 또는 사람이 정한다.

### 6. 통합

1. 통합 워크트리에서 슬라이스 브랜치를 순서대로 머지한다. 충돌은 `resolving-merge-conflicts` 스킬이 있으면 그 절차로, 없으면 양쪽 브리프의 계약 문장을 기준으로 푼다.
2. 통합 브랜치에서 전체 테스트와 수용 기준 전부를 한 번 돌린다. 슬라이스별 검증은 이미 했으므로 여기서만 전체를 돈다.
3. 통합 브랜치를 어디로 올릴지는 되돌릴 수 있는 형태(브랜치 푸시, MR/PR)를 기본으로 한다. `main` 직접 푸시나 force-push는 사람의 결정이다.
4. 합쳐진 슬라이스의 워크스페이스는 `herdr worktree remove --workspace <id>`로 닫는다. 브랜치는 통합이 올라간 뒤 지운다.

### 7. 보고

최종 응답에 슬라이스별 결과, 리뷰 회차 수, 남은 `blocking`, 통합 브랜치 이름, 실행한 검증 명령과 결과, 사람이 정해야 할 남은 결정을 적는다. `run.md`가 같은 내용을 담고 있어야 한다.

## 상태 파일

실행 디렉터리 `<state>`는 `${XDG_STATE_HOME:-$HOME/.local/state}/herdr-orchestrate/<run>/`다. 저장소 밖이라 워크트리를 더럽히지 않고 모든 워커가 절대 경로로 읽으며, 재시작 사이에 남는 사용자별 상태라는 XDG state의 정의에 맞다(`/tmp`는 보존 계약이 없고, 저장소 안은 워크트리마다 따로 있어 공유되지 않는다). `XDG_STATE_HOME`이 상대 경로면 규격대로 무시하고 기본값을 쓴다. 새 실행 디렉터리는 `mkdir -m 700 -p`로 만든다. agy 에이전트에게는 `--add-dir <state>`를 넘긴다.

```
<state>/
  run.md            목표, 수용 기준, 슬라이스 표(slice | depends | workspace | pane | agent | branch | state | rounds), 웨이브, 예산
  decisions.md      결정 기록: 질문, 선택지, 근거 URL, 결정자(쿼럼/사람), 반대 의견, 되돌리는 방법
  slices/<slice>/
    brief.md        워커 브리프
    report.md       워커 보고, 마지막 줄 REPORT_DONE
    review-<n>.md   회차별 리뷰
    handoff.md      워커 교체 시 인수인계
```

오케스트레이터의 컨텍스트가 압축되어도 `run.md`만 읽으면 이어 갈 수 있게 상태 변화마다 갱신한다. 예산은 슬라이스별 최대 리뷰 회차(기본 3)와 실행 전체의 벽시계 시간이며 `run.md` 머리에 적는다.

## 사람 개입

사람과 말하는 것은 오케스트레이터만이다. 워커·리뷰어·쿼럼 참여자는 `herdr-hitl`을 부르지 않고 질문을 `report.md`에 적는다. 질문마다 `herdr-hitl channel`을 먼저 실행하고, `terminal`이면 이 인터페이스에서, `messenger`면 `herdr-hitl ask`로 묻는다. 규약은 `herdr-hitl` 스킬을 따른다. 스케줄러(`herdr-cron` 등)가 띄운 무인 실행이면 어느 채널이든 `herdr-hitl`을 부르지 않고 막힌 지점을 `run.md`와 출력에 남긴다.

사람은 두 방식으로 개입한다.

- 인지. 사람은 사이드바에서 라벨과 상태를 보고 `run.md`를 읽는다. 웨이브가 끝나거나 루프가 멈출 때 `messenger` 채널이면 `herdr-hitl notify`로 한 줄 알린다. 질문이 아니므로 답을 기다리지 않는다.
- 통제. 사람은 어느 페인에나 들어가 직접 입력할 수 있다. 워커 페인에 사람의 입력 흔적이 보이면 그 지시를 브리프보다 우선하고, 이어 가기 전에 워크트리의 `git status`와 `report.md`를 다시 읽는다.

사람에게 넘기는 결정은 `herdr-hitl` 스킬이 정한 범주(되돌릴 수 없는 행동, 저장소가 답하지 못하는 진짜 트레이드오프, 사람만 가진 값, 상충하는 요구, 범위 밖)만이다. 기술적 갈림은 먼저 `herdr-quorum`으로 근거를 모은다. 사람이 결정할 문제라도 쿼럼의 권고와 반대 의견을 함께 보내서 사람이 빈손으로 정하지 않게 한다.

사람도 틀릴 수 있다. 사람의 답이 쿼럼이 확인한 사실(문서, 테스트 결과)과 어긋나면 그 근거를 한 번만 다시 보내고 확인을 구한다. 두 번째 답은 그대로 따르고 `decisions.md`에 결정과 반대 근거를 함께 적는다. 결정은 되돌릴 수 있는 형태(브랜치, 플래그)로 구현한다. 선호의 문제(이름, 스타일)는 재확인 없이 따른다.

## 이 스킬이 쓰는 다른 스킬

없어도 동작하지만 있으면 쓴다. `herdr`(CLI 세부), `herdr-hitl`(질문 규약), `herdr-quorum`(합의), `resolving-merge-conflicts`(통합 충돌), `handoff`(워커 교체 문서 형식). 리뷰는 다른 리뷰 스킬을 부르지 않고 review.md의 리뷰어 브리프로만 한다. 리뷰어가 diff만 보고 시작한다는 격리가 그 브리프에 들어 있기 때문이다.

설계 근거와 출처는 [references/sources.md](references/sources.md)에 있다.
