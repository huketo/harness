# T3 Show

목표는 *explorable explanation*이다. 사람이 스레드 안에서 직접 단계를 넘기고, 가정을 바꾸고, 데이터를 거르면서 스스로 이해하게 만든다. 설명 문단을 그림으로 옮기는 것이 아니라, 조작 하나가 이해 하나로 이어지도록 설계한다. 정적인 차트는 조작이 없는 특수한 경우다.

프레임 규칙(배경 없음, 테마 변수, 높이 범위, 금지 단위)의 정본은 `html_render` 도구 설명이다. 이 문서는 도구 설명에 없는 실행 환경과 설계·검증 절차만 다룬다.

## 실행 환경

T3 v0.1.3의 소스와 실측으로 확인한 사항이다. 버전이 바뀌면 다시 확인한다.

- **저장소 없음:** 페이지는 `allow-same-origin`이 없는 sandbox iframe에서 실행된다. `localStorage`, `sessionStorage`, IndexedDB, 쿠키는 예외를 던진다. 상태는 메모리에만 둔다. `html_preview`는 sandbox를 재현하지 않아서 저장소 호출이 성공하므로, 미리보기 통과를 근거로 삼지 않는다.
- **단방향:** 페이지는 에이전트에게 값을 돌려보낼 수 없다. 사람이 고른 값을 에이전트에게 알려야 하는 화면이면, 그 값을 `user-select: all`을 지정한 텍스트로 보여 준다. 프레임에는 클립보드 권한이 없으므로 `navigator.clipboard` 호출은 실패한다고 보고, 복사 버튼을 두려면 실패할 때 텍스트를 선택해 주도록 만든다.
- **외부 자원:** CSP는 sandbox만 지정하므로 CDN `<script src>`와 외부 `fetch`도 동작한다. 다만 사람이 페이지를 열 때마다 네트워크가 필요하고, 페이지는 스레드에 계속 남는다. 기본은 의존성 없는 JS·SVG·canvas로 쓰고, 라이브러리가 꼭 필요하면 `d3@7.9.0`처럼 정확한 버전을 고정한다.
- **데이터는 페이지 안에:** 에이전트 쪽 파일은 절대 경로로 지정한 로컬 이미지만 자동으로 인라인된다. 데이터는 `<script type="application/json">`에 넣는다. `html` 인자는 512,000자까지이므로 집계하거나 표본을 뽑아 줄인다.
- **높이는 따라간다:** `height`는 첫 높이일 뿐이다. 주입된 bootstrap이 `ResizeObserver`로 문서 높이를 보고하고, 프레임은 20000px까지 따라 커진다. 펼치기·접기는 써도 되지만, 재생 중에 화면이 출렁이지 않도록 무대·차트 영역의 높이는 고정한다.
- **테마 전환:** 사람이 테마를 바꾸면 bootstrap이 `<style id="t3-theme">`를 다시 쓴다. CSS 변수로 칠한 DOM·SVG는 저절로 바뀐다. canvas는 그 요소를 `MutationObserver`로 지켜보다가 `getComputedStyle`로 변수를 다시 읽어 그린다.
- **초기화는 가볍게:** 게시할 때 서버가 headless 브라우저로 여러 폭의 높이를 재는데, 제한 시간이 6초다. 무거운 계산은 셸에서 미리 끝내 결과를 넣거나, 첫 조작 시점으로 미룬다.
- **링크·키보드:** `http(s)` 링크는 호스트가 새 탭으로 연다. 입력 요소 밖에서 누른 단축키는 T3로 전달되므로, 페이지 전용 키(←, →, Space)는 처리한 뒤 `preventDefault()`를 호출한다.

테마 변수의 실측 관계는 다음과 같다. hex 값은 클라이언트 테마에 따라 바뀌므로 변수 이름으로만 쓴다.

- `--accent`와 `--chart-1`은 `--primary`와 같은 강조색이다. 옅은 면이 필요하면 `--accent-surface`, `--muted`, `--secondary`, `--card`를 쓴다.
- `--muted`는 면 색이고, 보조 글자색은 `--muted-foreground`다.
- dark에서 `--border`는 배경과 거의 구분되지 않는다. 구분선과 축은 `--muted-foreground`나 `color-mix(in srgb, var(--foreground) N%, transparent)`로 그린다.
- 입력 요소는 `accent-color: var(--primary)`로 테마를 따르게 한다.

## 용도별 설계

모든 용도에서 화면에 보이는 사실은 셸에서 확인한 근거에서 나온다. 페이지가 새로운 사실을 만들어 내지 않는다.

| 용도 | 중심 조작 | 근거와 자체 검사 |
|---|---|---|
| 코드베이스 설명 | 모듈 지도에서 노드를 고르면 책임·주요 함수·`path:line`이 상세 패널에 뜬다. 요청 하나의 흐름을 단계별로 재생한다. | 노드와 연결은 실제로 읽은 코드에서만 만든다. 한 화면의 노드는 15개 안팎으로 두고, 더 깊은 내용은 단계를 내려가며 보여 준다. |
| 알고리즘 이해 | 처음·이전·다음·재생과 속도 조절, 입력 편집. 현재 줄 강조와 변수·스택·큐 상태 패널. | 실제 구현을 셸에서 경계 사례를 포함한 2~3개 입력으로 실행하고, 그 출력이나 trace를 페이지에 넣는다. 페이지의 JS 재구현이 로드 시 그 값과 일치하는지 검사한다. |
| 시뮬레이션 (GTM 지표 등) | 가정 슬라이더와 숫자 입력, 기간별 결과 차트, 기본·낙관·비관 시나리오 비교. | 수식을 화면에 보여 주고, 기본값마다 출처(데이터 경로 또는 "가정")를 붙인다. 모델은 순수 함수로 쓰고, 기본값의 결과를 셸의 같은 계산과 대조한다. 난수는 seed를 고정한다. |
| 데이터 분석 | 필터, 정렬, 계열 토글, hover 툴팁, 구간 선택. | 집계는 셸(Python, DuckDB, SQLite 등)에서 하고 출처·질의·행 수·추출 시각을 함께 넣는다. 화면의 합계가 셸의 합계와 일치하는지 검사한다. 페이지는 스레드 첨부로 남으므로 분석에 필요한 최소한의 데이터만 넣는다. |

## 절차

1. **질문:** 사람이 이 화면으로 무엇을 이해하거나 결정해야 하는지 한 문장으로 정하고, 위 표에서 용도와 중심 조작 하나를 고른다.
2. **근거:** 코드를 읽고, 구현을 실행하고, 데이터를 집계한다. 페이지가 맞춰야 할 기대값을 이때 기록한다.
3. **작성:** 파일 하나에 `<style>`, 데이터 JSON, 순수 모델 함수, `render(state)`, 이벤트 처리기를 차례로 둔다. 상태는 객체 하나에 모으고, 모든 조작은 상태를 바꾼 뒤 `render`를 부르도록 쓴다. 기대값과 대조하는 자체 검사 함수를 넣는다. 검사가 실패하면 `console.error`로 남기고 화면에도 표시한다. 조작부의 배치와 시각 품질은 `awesome-interface`의 기준을 따른다. 자동 재생은 `prefers-reduced-motion`에서 멈춘다.
4. **확인:** `html_preview`로 아래 두 가지를 모두 확인한다.
   - 초기 화면: dark 728px, light 728px, dark 390px. 세 결과 모두 `consoleMessages`에 오류가 없고, 잘리거나 겹치거나 넘친 곳이 없어야 한다.
   - 조작: 페이지 끝에 미리보기 전용 driver `<script>`를 붙인다. driver는 대표 조작(단계 N회, 슬라이더 변경, 필터 선택)을 `click()`과 `dispatchEvent(new Event('input'))`로 수행하고, 그 결과 상태를 `console.log`로 남긴다. 스크린샷이 조작 뒤의 화면인지 보고, 기록된 값을 2단계의 기대값과 대조한다. 조작 종류마다 한 번 이상 실행한다.
   두 확인을 모두 통과하고 자체 검사가 성공한 뒤에 driver를 지운다.
5. **표시:** driver를 지운 HTML로 `html_render`를 호출한다. `height`에는 dark 728px 초기 화면의 `contentHeight`를 넣는다.

## 정적 그림

조작이 필요 없는 구조도는 `diagram-design`이 그림을 소유한다. 그 결과물을 스레드에 띄울 때는 [`references/diagram-design.md`](references/diagram-design.md)의 변환 절차를 따른 뒤, 위 4단계의 초기 화면 확인과 5단계를 수행한다.

사람이 다른 곳에 올리거나 보낼 이미지는 `html_render`를 거치지 않는다. 테마 변수에 기대지 않는 원본에서 `.png`를 만들어 경로를 준다. 다른 T3 스레드로 보낼 때는 `t3_attachment_prepare_upload`와 `t3_thread_send_attachments`를 쓴다.
