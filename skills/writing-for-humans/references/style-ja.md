# 日本語スタイルリファレンス

日本語でSNS・ブログの文章や技術文書を書くとき、または直すときに読む。[共通](#共通)の節は常に適用し、そのうえで文脈に合う節を一つ適用する（[SNS・ブログ](#snsブログ)、[技術文書](#技術文書)）。画面の文言は `awesome-interface` の `references/writing.md` が扱う。プロジェクトの用語集、文体の決まり、書き手の文体見本があれば、そちらをこの文書より優先する。

AIっぽい表現の型は直す候補であり、人が書いた文章かどうかの判定基準ではない。**強**の型は1か所でも直す。**弱**の型は、同じ段落にほかの型が重なるときだけ直す。引用、固有名詞、作品名、その表現自体を論じる文は直さない。

## 共通

### 事実と意味

- 原文と依頼者が示した事実だけを書く。名前、数値、日付、引用、原因、順位を新しく作らない。必要な事実がなければ文を簡単にし、確認事項として本文の外に書く。
- 直す前に保護する箇所を決め、文字どおり残す。数値と単位、引用、コード・コマンド・パス・URL、製品名と識別子が対象である。
- 書き直した案は原文と6点で比べる。主題、認める・否定する内容、動作主と相手、範囲と条件、言い切りの強さ（断定・推量・伝聞）、数値・固有名詞・時期である。1点でも変わる案は捨て、原文に戻す。
- 文の働きを変えない。伝聞（〜とのことです）を断定に、推量を事実に、依頼を予定に変えない。許可（〜してよい）、能力（〜できる）、説明（〜する）、保証（必ず〜する）を互いに入れ替えない。「〜することができる」を「〜できる」にするのは同じ強さなので構わない。

### 文体

一つの文書では敬体（です・ます）か常体（だ・である）のどちらか一つを使う。既存の文章があればそれに合わせ、なければ次の既定値を使う。

| 文脈 | 既定の文体 |
| --- | --- |
| SNS | アカウントがふだん使う文体。なければ敬体 |
| ブログ | 敬体か常体のどちらか一つ |
| 技術文書 | 共有・社外向けは敬体、仕様書や設計メモは常体も可 |

- 読み手との関係（社外、上司など）が示されたときだけ敬語を調整する。二重敬語や、原文にない「させていただく」を作らない。
- 文末をそろえるときは、勧め（〜しましょう）、決まり（〜します）、説明のどの立場かを先に決める。決められなければ文末をそろえない。

### 文

- 主語と述語、修飾語と係り先、指示語と指す対象が対応しているかを確かめる。主体や対象を補うのは、原文や示された資料から確定できるときだけにする。決まらなければ書き手に確かめる。
- 一つの文に一つの内容を書く。平均30〜45字、読点は1文に0〜2個を目安にする。目安であり上限ではない。条件と結果がまとまった長い文は、接続で向きが保てないなら分けない。
- 短い主語や主題の直後に、間を作るためだけに置いた読点は外す（「今回は、この方式で進めます」→「今回はこの方式で進めます」）。並べを区切る読点や、外すと係り先が変わる読点は残す。
- 比喩の動詞は、何がどう変わるかを書く平易な動詞にする。効く、溶かす、潰す、倒す、壊れる（データや処理が主語のとき）などが対象である。「うっかり」のような含みは残すが、技術文書では文体に合う語にする（「ガッツリ減る」→「大幅に減る」）。骨が折れる、手を焼くのような定着した慣用句は残す。
- 道具や概念に感情や意図を持たせた文を直す。「見積もりの甘さが判断を後ろ倒しにした」→「見積もりが甘く、判断が遅れた」。「このツールはログを集めます」のような客観的な動作の説明は残す。
- 英語の直訳調の言い回しを、日本語でふつうに言う形にする。「〜ことを意味しません」→「〜わけではありません」、「〜を可能にします」→「〜できます」。

### AIっぽい表現

| 型 | 例 | 直し方 | 強さ |
| --- | --- | --- | --- |
| 否定対比の演出 | 「単なるXではなく、Y」「これは努力ではない。才能でもない。仕組みだ。」 | 誰もXと主張していなければYだけを書く。誤解を正す否定は1文にまとめて残す | 強 |
| 前置き | 「結論から言うと」「重要なのは〜です」 | 外す。評価そのものが主張なら述語に移す（「〜が重要です」） | 強 |
| 予告だけの導入 | 「本記事では〜をご紹介します」 | 内容から書き始める | 強 |
| 定型の結び | 「いかがでしたでしょうか」「参考になれば幸いです」「ぜひ試してみてください！」 | 外す。メールの挨拶と結びは残す | 強 |
| チャットの名残 | 「良い質問ですね」「お役に立てれば幸いです」 | 外す | 強 |
| 流行の比喩語 | 解像度が上がる、手触り、意思決定OS、強固な土台 | 指しているものを文脈から言い換え、元の主張は残す（「組織の意思決定OSとしてのガバナンス」→「組織が意思決定するための枠組みとしてのガバナンス」） | 中 |
| 大げさな評価 | 飛躍的、画期的、劇的に、圧倒的 | 数値か具体的な事実にする。なければ外す | 中 |
| 根拠のない権威 | 「専門家によると」 | 出典を示すか外す | 中 |
| 装飾の書式 | 絵文字の見出しや箇条書き、意味のない太字、説明を繰り返す「**ラベル**：説明」 | 文か普通の箇条書きにする。日時・担当・数値などの値のラベルは残す | 中 |
| ダッシュ | 「重要な機能――特に認証――は」 | 読点、句点、括弧にする。小説や引用の意図した使い方は残す | 中 |
| 「のは、A、B、C。」 | 「変わったのは、速度、費用、運用。」 | 述語まで書く（「〜では、速度、費用、運用が変わった」） | 中 |
| 評価だけの短文の連続 | 「速い。軽い。安い。」 | 対象と評価を述語までつなぐ。宣伝文では残す | 弱 |
| 冗長な括弧 | 「修正前のAI生成文（素の出力）」 | 同じ意味の補足を外す | 弱 |
| 文頭の「もちろん、」 | 「もちろん、万能ではありません。」 | 必要な制約だけを文にする | 弱 |
| 内容を繰り返す「まとめ」 | 短い文書の末尾の要約 | 新しい情報がなければ外す | 弱 |

### 表記

- 句読点は「、」「。」を使う。プロジェクトが「，」を使っていれば一貫させる。
- 英数字は半角にする。横書きでは算用数字を使い、金額などは3桁区切りのカンマを入れる（「2,000円」）。慣用句や概数の漢数字は残す（「一つ」「数十件」）。
- 和文と英数字のあいだにスペースを入れるかどうかは原文やプロジェクトの書式に合わせ、自動で足したり消したりしない。
- カタカナ語の語末の長音は付ける（サーバー、ユーザー）。プロジェクトの表記があればそれに従う。
- 太字の内側が記号（「」、。（）など）で外側が文字のときは、表示されないことがある。括弧の内側だけを太字にするか、句読点を太字の外に出す（`「**文書の立場**」`）。
- コード、製品名、APIのフィールド、コマンドは翻訳しない。

## SNS・ブログ

- 書き手の文体見本があれば、文の長さ、語の選び方、句読点、文末を見本に合わせる。見本がなければ、書き手の意見、迷い、具体的な経験を残し、整った教訓を新しく足さない。
- 最初の文で何が変わったか、どういう状況かを書く。「ついに！」「知ってましたか？」のような前置きから始めない。
- リリースや告知の文章では、対応範囲、制限、決まっていない日程を隠さない。未定の日程は未定と書く。
- 資料の項目を1文に一つずつ書き写さない。読み手にとって大事な順に事実をまとめ、続く事実は接続でつなぐ。
- 資料に書かれた執筆上の指示（例：「価格はまだ公開しない」）は守るだけにし、投稿の文として書かない。
- 資料の語順や語をそのまま写さず、日本語でふつうに言う形にする。資料が他の言語のときも同じである（「3人がチャットに同時に参加」→「3人で同時にチャットに参加」、機能名はかぎ括弧で示す）。
- SNSの投稿一つに要点を一つにする。ハッシュタグは実際に検索される語だけを0〜3個にする。絵文字はアカウントの慣例があるときだけ使い、語の代わりにしない。「いいね・シェアお願いします」ではなく、リンクや情報で締める。
- 文字数の上限は投稿前に現在の値を確かめる。Xは日本語1文字を英字2文字として数えるため、通常のアカウントでは日本語の投稿は140字前後が上限になる。
- ブログ記事の構成は `writing-for-humans` の `post` ジャンルに従う。

## 技術文書

- 結論を先に書く。手順は番号付きの箇条書きにし、1手順に1動作を書く。条件は指示の前に置く。
- 用語は初出で定義し、同じ概念に別の表記を混ぜない。読み手が明示されていないときは専門用語を言い換えない。
- コード、コマンド、パス、設定キーはコード書式にする。
- 状態を正確に書く。調査中の原因を断定しない。試作、検証、ステージングを本番と書かない。見込みを「〜します」と言い切らない。
- 箇条書きの「ラベル：説明」は、値や名前に説明が続く項目にだけ使う。ラベルが説明を繰り返すときは、ラベルの意味を文に入れて1文にする。項目の数と順序は変えない。
- 議事録の体言止めや項目、PR説明のテンプレート見出し、障害報告の時刻ごとの箇条書きは、その文書の普通の書き方なので残す。

## 点検

1. 原文と比べて足した事実、消した事実が0件である。6点の比較で変わった点がない。
2. 文体（敬体か常体）が一つである。
3. 強の型が0件で、弱の型が重なる段落が0か所である。
4. 比喩の動詞、擬人化、間を作るだけの読点を点検した。
5. 絵文字、意味のない太字、ダッシュが残っていない（意図した使い方を除く）。
6. 句読点、英数字の半角、3桁区切り、長音の表記が一つにそろっている。
7. 適用した文脈の節の項目をすべて確かめた。
