# 이미지 프롬프트 패턴 선택

이 문서는 스타일 카탈로그가 아니라 짧은 요청을 구체화할 때 고르는 입구다. 원본 예제와 비슷하게 만드는 것보다 사용자의 주제, 용도, 매체, 제약을 지키는 것이 우선이다. 아래에서 가장 가까운 한 행을 고르고 [`patterns.json`](patterns.json)의 같은 `id` 객체만 읽는다.

| `id` | 고르는 경우 |
| --- | --- |
| `character-series` | 캐릭터 설정표, 표정·포즈 변형, 동일 인물의 연작 |
| `cinematic-space` | 풍경, 건축, 인테리어, 아이소메트릭 등 공간과 빛 중심 장면 |
| `poster-type` | 정확한 문구와 시각 위계가 필요한 포스터, 표지, 키비주얼 |
| `product-brand` | 제품 사진, 패키지, 로고, 브랜드 적용물 보드 |
| `diagram-process` | 단계, 관계, 경계, 예외를 설명하는 과정·시스템 도식 |
| `chart-evidence` | 실제 수치의 비교, 추세, 분포, 불확실성을 보여주는 차트 |
| `technical-cutaway` | 내부 층, 부품 순서, 조립 관계를 보여주는 단면·분해도 |
| `ui-preview` | 모바일 화면, 대시보드, 디자인 시스템의 시각 콘셉트 |

## JSON에서 한 그룹 읽기

1. `when`이 요청의 결과물과 맞는지 확인한다. 맞지 않으면 다른 행을 고른다.
2. `techniques`에서 요청을 선명하게 만드는 항목만 적용한다. 사용자가 정한 주제나 매체를 예제의 것으로 바꾸지 않는다.
3. `avoid`로 과잉 장식, 허구 데이터, 참조의 무단 전이를 걷어낸다.
4. `example.short_prompt`에서 `expanded_prompt`로 넘어가는 구조만 참고한다. 예제의 고유 명사, 문구, 색, 소재를 복사하지 않는다.
5. 장면·피사체·구도·빛·재질·정확한 문구·제약을 읽기 쉬운 순서로 쓴다. 참조 이미지가 있으면 번호와 역할을 밝히고, 편집은 바꿀 것과 보존할 것을 분리한다.
6. `example.checks`를 요청에 맞게 바꿔 결과를 검수한다. 후속 편집은 한 번에 한 가지를 바꾸고 보존 조건을 다시 적는다.
7. `aspect_ratio`는 구도 의도다. 모델, 품질, 크기, 배경 같은 API 설정은 프롬프트 문장과 분리하고, 런타임이 특정 모델 버전을 쓴다고 가정하지 않는다.

프롬프트 구조와 편집 원칙은 [OpenAI 이미지 프롬프팅 가이드](https://developers.openai.com/api/docs/guides/image-prompting?model=gpt-image-2.5)를 따른다. 출처와 대표 원문 링크는 JSON의 `source`, `source_ids`, `source_urls`에 있다. `source.license`는 표시된 원본 저장소에 관한 정보이며, 연결된 외부 저자·브랜드·지식재산의 권리를 보장하지 않는다.

## 짧은 전이 예시

- “수중 우편배달부 캐릭터를 여러 표정으로” → `character-series`: 수중 우편배달부라는 주제를 유지하고, 변하지 않을 얼굴·복장과 달라질 표정을 나눈다. 예제의 달 기지 정비사나 화풍은 옮기지 않는다.
- “분기별 반품률을 비교해줘” → `chart-evidence`: 실제 값, 단위, 기간, 집계 기준을 먼저 받는다. 이미지 생성은 레이아웃 시안에만 쓰고, 정확한 납품 차트가 필요하면 같은 데이터로 SVG·차트·PPT를 구현한다.

## 정확성 및 산출물 경계

교육·연구·수치 이미지는 사실이나 레이블의 정확성을 보장하지 않는다. 실제 데이터와 확정된 레이블을 입력하고, 결과의 숫자·철자·화살표·관계를 해당 분야 사람이 의미 검수한다. 래스터 도식, 차트, UI 목업은 콘셉트 이미지다. 편집 가능한 SVG, 재현 가능한 차트, PPT 도형, 접근 가능하고 작동하는 UI가 필요하면 적합한 제작 도구에서 별도로 구현하고 검증한다.
