# img-gen

사용자의 새 주제를 이미지 제작 명세로 바꾼다. 참고 예제는 **표현 기법의 자료**이지 닮게 만들어야 할 정답이나 지원 범위 목록이 아니다. GPT Image 2.5 프롬프팅 가이드를 바탕으로 하되, 프롬프트의 대상 모델과 실제 네이티브 도구의 백엔드 버전을 구별한다.

## 1. 요청과 산출물

생성, 원본 편집, 프롬프트만 작성 중 무엇인지 판단한다. 프롬프트만 요청했으면 유료 생성 도구를 호출하지 않는다. 기존 이미지의 편집·참조 요청이면 파일을 먼저 열어 무엇을 보존해야 하는지 확인한다.

목적, 주제, 필요한 문구, 종횡비, 필수 보존 조건을 추출한다. 용도에서 안전하게 정할 수 있는 구도·조명은 제안해 진행하고, 요청을 장문의 설문으로 바꾸지 않는다. 정확한 문구나 식별해야 할 입력처럼 결과를 좌우하는 누락만 묻는다. 사용자가 정한 스타일·구도·문구가 예제보다 우선이다.

정확한 수치나 편집 가능한 산출물이 필요한 경우 이미지를 대용으로 내놓지 않는다. SVG 도식, 데이터 기반 차트, 작동하는 UI, 편집 가능한 슬라이드는 적절한 제작 도구로 넘긴다. 사용자가 래스터 컨셉 이미지를 원하면 생성하되 원본 데이터와 의미를 별도로 검사한다.

## 2. 참고 기법 선택

표현 방식이 열려 있거나 짧은 요청의 품질 조건을 보완할 때 [기법 선택표](references/patterns.md)를 읽는다. 해당 `id`의 `references/patterns.json` 항목을 읽고 필요한 기법만 가져온다. 모든 예제를 매번 읽거나 원본 이미지를 자동으로 입력에 첨부하지 않는다.

- 비슷한 예제는 하나의 기법으로 묶고 새로운 주제에도 적용한다.
- 예제의 인물·상표·문구·장소를 사용자의 주제에 섞지 않는다.
- 작가·작품 이름 대신 필요한 색, 재질, 구도, 매체 특성을 설명한다.
- 참고가 맞지 않으면 예제를 사용하지 않는다. 프롬프트가 길어지는 것 자체는 개선이 아니다.

## 3. 생성 명세

간단한 요청은 짧은 자연어 문장으로 유지한다. 복잡할 때만 다음 순서로 구분한다.

1. **목적·피사체:** 무엇을 보여주고 어떤 용도로 쓰는가.
2. **구도:** 시점, 배치, 상대 크기, 잘림, 필요한 여백.
3. **표현:** 매체, 표면 재질, 조명, 색상. 요청과 무관한 cinematic·premium 같은 수식어를 자동 추가하지 않는다.
4. **문자:** 정확한 문자열을 인용하고 위치·횟수·가독성을 지정한다. 한국어를 영어로 바꾸거나 문구를 임의 교정하지 않는다.
5. **참조:** 입력마다 정체성·구도·의상·질감 등 역할과 가져오지 않을 요소를 지정한다.
6. **편집:** 변경할 부분과 유지할 부분을 분리한다. 프롬프트만으로 픽셀 동일성을 보장하지 않는다. 동일 픽셀 보존이 필수면 원본과의 국소 합성을 사용한다.
7. **검수 조건:** 이번 요청에서 관찰 가능한 조건 몇 개만 적는다.

수치·교육·연구 그림에는 제공된 데이터·레이블·관계를 직접 넣는다. 없는 통계나 인용을 그럴듯하게 만들지 않는다. 예시 데이터라면 이미지 안에도 예시임을 표시한다.

크기, 품질, 형식, 투명 배경 같은 실행 옵션은 프롬프트와 별도로 관리한다. 자세한 설정이 필요할 때 [GPT Image 2.5 원칙과 설정](references/prompting.md)을 읽는다.

## 4. 네이티브 실행

[런타임별 실행](references/runtimes.md)을 읽고 현재 제공된 도구 스키마를 확인한다. 기존 구독·인증을 사용하는 네이티브 경로가 기본이다. 인증 파일을 읽거나 토큰을 추출하지 않는다. API 결제 경로 또는 다른 제공자로 조용히 전환하지 않는다.

기본은 한 장이다. 사용자가 변형·비교·배치를 요청했을 때만 그 범위로 늘린다. 배치를 병렬 실행할 때는 결과 경로를 작업별로 분리하고 에이전트 모델과 이미지 백엔드를 각각 기록한다.

도구에 이미지 모델 선택이 있으면 요청된 지원 모델을 지정한다. 모델 선택 필드가 없으면 네이티브 기본값을 사용한다. 모델 출처 확인이나 비교가 필요하면 [C2PA 출처 검사](references/provenance.md)를 따라 원본 매니페스트와 신뢰 수준을 확인한다. 도구·C2PA 모두 버전을 제공하지 않으면 **이미지 모델 버전 미확인**으로 보고한다. GPT 에이전트 이름이나 AGY 대화 모델 이름을 이미지 백엔드 이름으로 바꾸어 쓰지 않는다.

도구가 반환한 이미지의 존재와 실제 형식을 확인하고, 원본 artifact를 유지한 채 합의된 결과 경로로 복사한다. 도구 오류·빈 응답·프롬프트 파일만으로 생성 성공을 선언하지 않는다.

## 5. 검수와 수정

결과 이미지를 직접 열어 요청 조건과 비교한다.

- 문구: 철자, 등장 횟수, 읽기 쉬운 크기, 잘림.
- 구도: 피사체 수와 배치, 여백, 손잡이·팔다리 등 필수 부분.
- 편집: 정체성·제품 형상·레이블과 변경하지 않을 영역.
- 도식: 데이터, 라벨, 화살표 방향과 연결 관계. OCR은 보조 수단이다.
- 투명도: 실제 알파 값과 밝고 어두운 배경에서의 경계. 체크무늬 그림은 투명도가 아니다.

실패한 조건만 좁혀 이전 결과를 입력으로 수정하고 보존 조건을 반복한다. 생성 결과를 보지 않고 재생성하지 않는다. 자동 수정은 한 차례로 제한하고 더 필요한 시도는 문제와 비용을 드러내어 사용자의 지시를 받는다. 비교 실험에서는 최초 결과도 남긴다.

## 6. 전달

이미지 경로, 사용한 기법과 주요 실행 옵션, 실제 런타임·확인된 이미지 모델 또는 미확인 표시, 검수 결과와 남은 문제를 짧게 전달한다. 프롬프트 전용 요청이면 최종 프롬프트와 추천 설정만 제공한다.

원본 참고와 새 결과를 비교할 때는 [카탈로그·비교 제작](references/catalogs.md)을 읽는다. 유사도가 아니라 **새 요청의 충족과 기법의 전이**를 비교한다. 서로 다른 프롬프트·해상도·재시도 조건을 같은 조건의 성능 대결로 표현하지 않는다.
