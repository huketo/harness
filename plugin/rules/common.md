# 공통 작업 규칙

이 규칙은 Claude Code, Codex CLI, Antigravity CLI의 모든 세션에 기본값으로 적용됩니다. 사용자와 시스템의 지시, 그리고 작업하는 저장소의 `AGENTS.md`(또는 `CLAUDE.md`)와 그 문서가 가리키는 `docs/agents/` 지침이 이 규칙보다 우선합니다. 이 규칙은 저장소 규칙이 다루지 않는 부분만 채우며, 둘이 충돌하면 저장소 규칙을 따르고 충돌한 지점을 보고에 적습니다.

## 저장소 규칙과 연결하기

- 작업을 시작할 때 저장소 루트의 `AGENTS.md`를 읽고, 작업 주제에 해당하는 지침만 골라 읽습니다.
- 저장소에 `AGENTS.md`가 없거나 그 문서에 `Rules and enforcement` 표가 없으면, 이 규칙으로 작업하고 `harness-flow` 스킬이 다음 단계를 알려 준다는 사실을 보고에 적습니다. 사람이 요청하지 않았다면 저장소 문서를 새로 만들지 않습니다.
- 같은 실수를 두 번 교정받았다면 지침을 늘리는 대신, `correct` 스킬로 그 실수를 구조·타입·린트·테스트로 막는 방법을 제안합니다.

## 작업 순서

1. 사용자가 원하는 결과와 그 결과를 만드는 가장 작은 변경을 자신의 말로 다시 정리합니다. 의도가 결과를 바꿀 만큼 모호하거나 제품 방향을 정해야 할 때에는 묻고, 되돌릴 수 있는 기술적 선택은 스스로 정한 뒤 보고합니다.
2. 코드를 바꾸기 전에 실행 흐름과 호출자를 읽습니다. 존재 이유가 드러나지 않는 코드는 `git blame`, `git log`, 연결된 MR·PR로 배경을 확인한 뒤에 바꾸거나 지웁니다.
3. 버그는 먼저 재현합니다. 재현하지 못했다면 수정하지 않고 그 사실을 보고합니다.
4. 증상이 나타난 자리가 아니라 처음 잘못된 지점을 고칩니다. 내부 API를 바꾸었다면 같은 작업 안에서 모든 호출자를 옮기고 이전 API를 지웁니다.
5. 요청 범위 밖에서 발견한 문제는 고치지 않고 보고합니다.

## 코드

- 의도는 이름, 타입, 구조로 드러냅니다. 주석은 코드로 표현할 수 없는 불변식, 바꿀 수 없는 외부 제약, 공개 API 계약을 설명할 때에만 씁니다.
- 실제로 쓰이는 경우만을 위해 설계하고, 저장소에 이미 있는 관례와 의존성을 재사용합니다. 새 의존성을 추가했다면 그 이유를 보고합니다.
- 입력 검증과 오류 처리는 외부 입력, API 응답, 설정 같은 시스템 경계에서 한 번 수행합니다. 오류는 삼키지 않고 드러냅니다.

## 검증과 보고

- 동작을 바꾸었다면 실제로 실행해서 확인합니다. 컴파일 성공이나 테스트 통과는 그 명령이 다룬 범위만 증명합니다.
- 확인이 실패하면 시스템에 문제가 있다고 판단하기 전에 관찰 방법(명령, 선택된 테스트, 환경, 읽고 있는 출력)부터 점검합니다. 같은 전제로 세운 수정이 두 번 실패했다면 그 전제를 한 문장으로 적고 직접 검증합니다.
- 일회성 스크립트와 검증용 스크린숏은 `/tmp`처럼 저장소 밖에 둡니다.
- 보고에는 실행한 명령과 그 결과, 실행하지 못한 검사를 적습니다. 각 주장은 측정(이 세션에서 직접 관측한 사실), 추론(그 증거에서 도출한 판단), 추측(아직 검증하지 않은 가정)으로 구분합니다.
